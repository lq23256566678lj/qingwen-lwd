# 已知限制

轻文当前是 v0.1，目标是把“常用写作”做稳，而不是覆盖 Word 的全部能力。以下是明确的能力边界与取舍，避免把它们误认为 bug。

## 1. 格式与互操作

- **不兼容 `.docx`**：不读取、不写入、不转换 Office 文档。`.lwd` 是自定义 JSON，不能用 Word 直接打开。
- **没有 PDF 导出**：仅支持纯文本与独立 HTML。HTML 可以在浏览器中打印为 PDF，但分页、页眉页脚、页码由浏览器决定，不是编辑器排版结果。
- **HTML 导出是静态快照**：保留文字样式、表格、图片（data URL）与基本排版；不包含编辑器的交互能力、缩放控件、搜索高亮。
- **纯文本导出会扁平化结构**：表格单元格、列表项会以换行分隔，不保留制表符、项目符号、缩进层级。
- **无版本历史 / 修订模式 / 批注 / 脚注 / 目录**：只有单份当前内容，撤销栈不持久化。
- **未知节点不保证向前兼容**：打开更高版本的 `.lwd` 会直接拒绝；未知节点会触发严格加载错误，而不是静默丢弃。

## 2. 编辑能力

- 标题仅 1–4 级，不支持自定义样式集、主题字体、段落样式。
- 不支持行距、段前段后、首行缩进、制表位、分栏、页面大小/页边距、页眉页脚。
- 不支持文本上标/下标、小型大写、字距、字符缩放、艺术字。
- 不支持数学公式、脚注、尾注、目录、交叉引用、书签。
- 不支持批注、修订、协作、多人光标。
- 超链接仅保留为 mark，**不会在应用内直接打开**（避免 WebView 被导航到任意站点）；可在导出 HTML 中点击。
- 原生“格式”菜单项未显示快捷键；快捷键由编辑器 keymap 直接处理。文件菜单的快捷键会与前端兜底监听去重。
- 表格：
  - 不支持公式、排序、单元格合并后的复杂拆分策略、单元格底色/边框/垂直对齐；
  - 不支持行列拖拽排序、嵌套表格、表格标题/题注；
  - 拖拽列宽依赖 TipTap 的 `colwidth`，在超宽表格和窄窗口下可能出现横向滚动。
- 图片：
  - 不支持图注、替代文本编辑界面、图片对齐方式（仅块级居中显示）；
  - 不支持 SVG；不支持从网页直接粘贴远程图片（只处理剪贴板中的图片文件/位图）；
  - 缩放后的宽高写入节点属性，但没有“恢复原始尺寸”的按钮。
- 查找替换：
  - 字面量匹配，不支持正则、全词匹配、搜索历史；
  - 不跨段落/表格单元格匹配；
  - 大小写不敏感使用 JS `toLowerCase`，对少数大小写转换会改变长度的 Unicode 字符，位置映射可能不准确；
  - 替换文本不支持多行结构化插入（会作为文本插入）。

## 3. 图片与大文档

- 图片以 Base64 内嵌，文件体积比原图增大约 33%；一张 5 MB 的照片会变成约 6.7 MB 的 JSON。
- 单张源图上限 **12 MB**；最长边压缩到 **1600 px**；整个 `.lwd` 上限 **128 MB**。
- 压缩在 WebView 中通过 canvas 完成，超大图片会造成短暂主线程卡顿。
- 不支持图片资源外链；所有图片随文档复制，适合便携，不适合大量图库型文档。
- 当前没有虚拟滚动；数万段/数十张大图时，整篇 `getJSON()` 序列化、字数统计与工具栏重渲染会变慢。

## 4. 自动保存与文件安全

- **最后写入者获胜**：如果另一个程序（或另一台机器上的同步盘）同时修改同一个 `.lwd`，轻文的自动保存可能覆盖外部修改。没有文件锁、冲突检测或合并。
- 自动保存有约 0.9–2.4 s 的防抖窗口；进程被强杀/断电时可能丢失最后不到 1 秒的输入。15 s 兜底只能降低概率，不能消除。
- 草稿只保留最后一份，且存放在应用数据目录，不加密；同一操作系统账户下的其他程序可以读取。
- 成功保存、放弃修改、新建或打开其他文档时会删除草稿。若在“放弃修改”后取消了打开对话框，当前文档仍保持未保存状态，但草稿可能已被清除（下一次输入会重新生成）。
- 不使用系统 `fs` 插件；文件路径由对话框或拖放提供。没有“最近文件”列表、文件关联/双击打开、单实例转发。
- 关闭窗口的未保存提示依赖 WebView 的 `onCloseRequested`；强制结束进程（任务管理器、`kill -9`）不会弹窗，只能依赖草稿恢复。

## 5. 平台与输入法

- 代码按 Tauri 2 的跨平台 API 编写，macOS / Linux 已由 GitHub Actions 成功构建；但**未在 macOS / Linux 真机上完成运行回归**，主要风险点是原生菜单布局、⌘ 加速键、WebKitGTK 的字体与输入法行为。
- Linux 需要额外的 WebKitGTK 系统依赖；不同发行版的输入法（fcitx5 / ibus）行为可能与 Windows 不同。
- 中文输入法：已避免在 composition 期间抢快捷键、避免受控组件重写内容；但不同 IME 版本的候选框定位、标点转换、emoji 输入仍可能有个体差异，需要按输入法逐一验证。
- 无自定义标题栏：使用系统原生窗口装饰；macOS 的交通灯与 Windows 的标题栏样式由系统决定。
- 高 DPI 下使用 CSS 像素布局，WebView 缩放由系统控制；没有编辑器缩放功能。

## 6. 构建与交付

- GitHub Actions 的 `build` workflow 已在三个平台成功构建：
  - Windows `windows-latest`（MSVC）：NSIS + MSI；
  - macOS `macos-latest`：universal DMG；
  - Linux `ubuntu-22.04`：AppImage / DEB / RPM。
- 本地交付环境没有 MSVC/Windows SDK；本地完成了 `cargo fmt --check`、GNU 目标的 `cargo check` 与 `cargo build` 链接验证，以及前端 `tsc`/Vite 生产构建。MSVC 构建由 CI 完成。
- 在具备 Tauri 前置依赖的机器上，请先 `pnpm install`，再执行 `cargo tauri build`。首次打包需要网络下载 WiX/NSIS。
- 未配置代码签名、公证、自动更新；macOS 分发给他人时需要自行签名/notarize，Windows 可能出现 SmartScreen 提示。
- 跨平台产物由 GitHub Actions 在对应系统上构建；Tauri 不支持交叉打包 macOS/Linux 安装包。
- 单元测试代码已随 `storage.rs` 提供，但 GNU 测试可执行文件在交付环境中因运行时 DLL 搜索路径未成功运行；不影响库与主程序的编译链接。

## 7. 无障碍与其他

- 工具栏按钮有 `aria-label`/`title`，模态框实现了基础焦点圈定与 Esc 关闭；但 contenteditable 的无障碍语义仍受 ProseMirror/WebView 限制，屏幕阅读器体验未专门优化。
- 颜色选择器提供预设色板与原生 color input，但没有对比度检查；高亮/字体颜色可能降低可读性。
- 没有拼写检查、自动更正、字数目标、写作统计、专注模式、打字机模式。
- 界面语言仅简体中文；`.lwd` 本身不限制文档语言。
- 单窗口应用，没有多标签、分屏、拖出窗口；同时打开两个实例可能争用同一草稿路径（后写入者覆盖）。

## 8. 安全边界

- 图片只接受 PNG/JPEG/WebP/GIF（magic bytes），拒绝 SVG；导出 HTML 时会把文档内容直接嵌入，导出文件可能包含用户自己插入的链接，分享前请自行检查。
- CSP 在生产环境禁止内联脚本与外部网络请求；开发环境使用单独的宽松 CSP 以支持 Vite HMR。
- 不提供密码保护、文档加密、权限控制。`.lwd` 是明文 JSON，任何能读取文件的人都能看到内容。

## 可能的后续优先级

1. 在 Windows/macOS/Linux 真机上补输入法与菜单回归。
2. 文件锁/冲突检测与“最近文件”。
3. 大文档性能：按块序列化、编辑器内增量字数统计、工具栏状态选择器。
4. 图片外置资源模式（可选），在“自包含”和“小文件”之间给用户选择。
5. 正则查找、跨块匹配、多行替换。
6. 打印/PDF 导出与页面设置。
